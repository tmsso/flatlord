# Decisions — standing choices, not to be re-litigated

One line each. A session that wants to change one opens it as a question to the admin; it does not quietly pick differently. Status: **decided** / **proposed** (awaiting admin confirmation) / **open** (admin input needed before the dependent work can start).

| ID | Decision | Status | When / where |
|---|---|---|---|
| D-01 | **Drizzle for schema-as-code, migrations and the backup dump only; supabase-js for every app read/write** so RLS is always in the path. Don't add Drizzle queries in app code. | decided | Phase 0; confirmed in the 2026-09-15 review |
| D-02 | **Auth = Google OAuth + emailed magic link, invite-only, no self-signup.** Owner/tenant role on `profiles`. | decided | Design session, Phase 0 |
| D-03 | **Statements are retroactive by design.** A statement issued on/after its nominal due date isn't overdue until 7 days after issuance (`RETROACTIVE_ISSUE_GRACE_DAYS`). | decided | 2026-09-10, PR #31 |
| D-04 | **Replace formal phase-Accept gates with the admin-actions checklist in `ROADMAP.md`.** Gates were suppressed at every transition; no phase was ever Accepted. | decided | 2026-09-15 review; admin confirmed 2026-09-15 |
| D-05 | **Due-date semantics for newly issued statements.** Today `due_date` = `due_day` of the *period* month, so a statement for August issued on 20 Sep shows "due 5 Aug" to the tenant — legally nominal, practically confusing, and it is what forced D-03. Options: (a) keep as is; (b) `due_date` = `due_day` of the month *after issue* (matches "utilities reimbursed with next month's rent"); (c) `due_date` = issue date + N days. **Decided: (b)** — `due_date` = tenancy `due_day` of the month after the issue date. Historical months keep the sheet's dates. | decided | 2026-09-15 review; admin confirmed 2026-09-15 — implement as `BACKLOG.md` B-06 |
| D-06 | **Ad-hoc notes visibility & audit.** Admin-only, or per-note tenant-visible toggle? Do note edits get before/after audit like person fields? **Tentative (admin, 2026-09-15): admin-only v1 with a `visible_to_tenant` boolean defaulting false; edits audited via `logAudit()`.** The admin wants more detail before it's final — a session picking up ad-hoc notes must present a short design note (data shape, where notes surface, what the tenant toggle shows, what an audit row looks like) and get a go-ahead before writing a migration. | tentative — revisit | ROADMAP 4b |
| D-07 | **Historical statements show raw machine charge names.** Do not edit issued rows. Resolve a display label at render time from `charge_types.code` via the i18n catalog; stored description is the fallback. | decided (admin 2026-09-15) | 2026-09-15, `BACKLOG.md` B-07; history in memory `flatlord_charge_type_i18n_gap` |
| D-08 | **Nav wayfinding = icons + highlighted active item, one accent colour.** Per-section accent colours are dropped — they conflict with CLAUDE.md §5's one-accent rule and the icon/active-state pair already answers "where am I". | decided (admin 2026-09-15) | 2026-09-15, PR #34 |
| D-09 | **Sensitive person fields stay `"[redacted]"` in the audit trail for every viewer, including admin** (`NEVER_LOG_KEYS`). | decided | 2026-09-03 |
| D-10 | **Demo mode = `is_demo` flag in the production DB, not a second Supabase project.** | decided | IDEAS.md, 2026-08 |
| D-11 | **Extensible type columns are `text` + `CHECK`, not Postgres enums** (enum extension + use in one migration transaction fails under drizzle's migrator). | decided | Phase 2 |
| D-12 | **Money columns are currency-neutral** (`amount` + `currency char(3)`), HUF is a default not a name. | decided | CLAUDE.md §6 |
| D-13 | **Vercel Serverless Functions pinned to `fra1`** to sit next to the Supabase project in `eu-west-1`. Hobby plan allows one region. | decided (admin 2026-09-15) | 2026-09-15, PR #34 |
| D-14 | **Prod migrations only through `.github/workflows/migrate-prod.yml`**; never hand-applied. | decided | 2026-08 after two drift incidents |
| D-15 | **The tenant is never shown a cumulative total-paid-to-date.** Analytics loaders must not be imported under `src/app/(tenant)`. | decided | Owner, 2026-08-03 |
| D-16 | **Scanned-contract OCR is Phase 5**, not a Phase 2 retrofit; digital-text PDFs parse today. | decided | 2026-08-16 |
| D-17 | **Keep shadcn v4 base-nova / Base UI primitives; restyle `components/ui/*` toward the design tokens** (borders, shadows, radii, sizes) instead of swapping libraries or buying a UI kit. The design handoff is the spec. | decided (admin 2026-09-15) | 2026-09-15, started with `Card` in PR #34 |
| D-18 | **CI tests run against a real Supabase Postgres** (`supabase db start`) with the repo's migrations and demo seed — no mocks for RLS. | decided | Phase 0/1 |
| D-19 | **No paid subscriptions for now.** A domain is the one purchase recommended (unlocks Resend). Vercel Pro / Supabase Pro are not needed at this scale; revisit when a second owner/property arrives or a free-tier limit actually bites. **Registrar: not Vercel's** (first-year promo, marked-up renewals) — use Cloudflare Registrar (wholesale cost, flat renewals; DNS there, proxy *off* on the Vercel records) or Porkbun. | decided (admin 2026-09-15) | 2026-09-15 review |
| D-20 | **Cron never auto-issues.** Auto-draft creates `draft` statements only; issuing, notices and anything with tenant-facing legal weight stay manual. | decided | 2026-09-10, PR #31 (Trust rule) |
| D-21 | **Phase 4c (UI fidelity) items 1–2 run before the remaining 4b items.** The owner's stated concern is the look; 4b's leftovers were blocked on D-06 anyway. | decided (admin 2026-09-15) | 2026-09-15 review |
| D-22 | **App time zone is Europe/Budapest** (next-intl `timeZone`), not the server's. Vercel runs in UTC, so timestamps had shown UTC wall-clock time. Per-property zones only if a property outside Hungary ever appears. | decided | 2026-10-08, PR #50 |
| D-23 | **Statement delivery log is append-only and honest.** Emails log `sent`/`failed` with Resend's id; WhatsApp logs `prepared` (the wa.me link opens on the admin's own phone — the app can't know it was sent). Owner-only; no tenant view. | decided (built default, owner may revisit) | 2026-10-08, PR #49, migration `0028` |
| D-24 | **Corrections to an issued statement go on the next draft as ± adjustments; no in-place "+ Add adjustment" on an issued statement** (design/05 shows one). Matches the engine (adjustments target a month's draft) and §3.3's immutability. | decided (owner confirmed 2026-10-12) | 2026-10-08, PR #49 |
| D-25 | **Owner's name removed from the public repo's current files only; git history not rewritten** (force-push would break SHAs referenced in docs/memory, and GitHub may retain old commits anyway). | decided (owner, 2026-10-08) | PR #41 |
| D-26 | **A tenant blocked by the "≥ previous" rule escapes via a request, not an override**: "Send a note to the owner" opens a `billing_question` request with the facts, then the meter can be skipped. Only the admin overrides. | decided (design/03; built) | 2026-10-08, PR #52 |
| D-27 | **Facilities live in `inventory_items` as `kind = 'facility'`**, not a separate table; a CHECK pins them owner-owned. They reuse attachments, RLS, audit and the repair picker. | decided (owner: defaults, 2026-10-11) | Long batch 2026-10-11, PR #60, migration `0030` |
| D-28 | **"Full" reconfirmation campaigns cover movable items only**; facilities can still be picked in a subset campaign. | decided (owner: defaults) | PR #60 |
| D-29 | **RLS policies never subquery their own table directly**; stored-row reads go through `SECURITY DEFINER` SQL functions in the `private` schema (not exposed by PostgREST, so not callable over RPC as an oracle). A plain self-subquery recursed on `requests` (0029, caught on dev). | decided | PRs #59/#62, migrations `0029`/`0031` |
| D-30 | **Schema-dependent PRs merge only after prod has their migration**: run `migrate-prod.yml --ref <branch>` (or the top of a stacked chain) first. Adding a column is not "fail open" — selecting a missing column errors. Once prod has run a migration, it is frozen; fixes are new migrations (drizzle's migrator goes by timestamp, not hash). | decided (owner: defaults, 2026-10-11) | Long batch 2026-10-11 |
| D-31 | **Inventory `kind` is convertible** between item and facility for owner-owned rows (the owner-owned CHECK still applies); built as `BACKLOG.md` B-38. Originally proposed as "fixed at creation". | decided (owner 2026-10-12: "convertible") | PR #60; 2026-10-12 |
| D-32 | **The taxation module is an aid, not tax advice**: Hungarian defaults (15% rate, 10% cost ratio, quarterly advances) are pre-filled but every parameter is editable per year, the UI carries a disclaimer, and the module never files anything. Keep it simple — no attempt to model every rule. | decided (owner request 2026-10-12) | B-44 |
| D-33 | **Optional modules are switchable per owner**; taxation, inventory, requests and notifications default **off** for a new owner and sit under "Inactive modules" at the bottom of the menu; existing owners keep what they use. Off hides, never deletes. | decided (owner request 2026-10-12) | B-45 |
| D-34 | **Owners are isolated from each other.** An owner sees a person if it is themselves, they manage it (`persons.managed_by_person_id`, set on create) or it is linked (tenant / occupant / co-owner) to a property they own; linking a person requires seeing it already; audit rows are property-scoped (trigger-derived) plus person-visibility plus own actions. Same rule for person attachments/ID scans and invites. | decided (built; owner "defaults" 2026-10-12) | Long batch 2026-10-12, PR #78, migration `0032` |
| D-35 | **Field editability is per root property.** Global `field_policies` rows are read-only built-in defaults; at `0032` they were copied to every owned property so nothing changed for existing owners. | decided (owner "defaults" 2026-10-12) | PR #78 |
| D-36 | **The in-app backup export is "what you can see"**, run as the calling owner under RLS; the complete all-owners copy is the nightly GitHub backup only. | decided (built default — owner may revisit) | PR #78 |
| D-37 | **Module semantics (B-45):** "notifications" = the bell + automatic reminders (payment due, overdue, meter reading, contract expiry, rate review, inventory action-by); owner-initiated core emails (statement issued, notices) still go out. A property's module is on for its tenants and crons if **any** of its owners has it on; an owner's own UI follows only their own switches. A failed lookup in the cron assumes "on". | decided (built default — owner may revisit) | PR #80, migration `0033` |
| D-38 | **An owner invite without a person creates a bare person for the invitee** (name = email local part, renamed by them), visible only to them — the inviter is never asked for, and never sees, the new owner's personal data. B-42's "own personal data" step is the proper UX later. | decided (built default — owner may revisit) | PR #81, migration `0034` |
